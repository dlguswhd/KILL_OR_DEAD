# Unity 저장소 Git 사전 점검

Unity 프로젝트에서 커밋할 때 흔히 사고가 나는 지점을 커밋 전에 확인한다. 이 문서는 `commit` 스킬이 참조한다.

## 1. 절대 커밋하면 안 되는 경로

Unity가 자동 생성하거나 개인 환경에 종속되는 파일. staged에 있으면 경고하고 제외한다.

| 경로/패턴 | 이유 |
|---|---|
| `Library/` | Unity가 자동 생성, 수 GB, 사람마다 다름 |
| `Temp/`, `Logs/`, `obj/` | 임시 파일 |
| `UserSettings/` | 개인 에디터 설정 |
| `*.csproj`, `*.sln`, `*.slnx` | IDE가 자동 생성 |
| `.vs/`, `.idea/`, `.vscode/` | 개인 IDE 설정 |
| `Assets/**/*.zip`, `*.rar`, `*.7z` | 이미 압축 해제된 원본, 낭비 |

확인:
```
git status --porcelain
```
staged에 위 패턴이 있으면 `git restore --staged <path>`로 제외하고 사용자에게 알린다.

## 2. `.meta` 파일 동반 여부

Unity는 모든 에셋에 `.meta`(고유 GUID 포함)를 만든다. `.meta` 없이 에셋만 커밋하면 **다른 팀원 쪽에서 프리팹/씬의 참조가 전부 끊긴다.**

- 신규 파일이 staged인데 짝이 되는 `<file>.meta`가 빠져 있으면 함께 추가한다.
- 반대로 짝 없는 `.meta`만 커밋되지 않도록 주의한다.

## 3. 씬 / 프리팹 변경

`.unity`, `.prefab`은 자동 병합이 거의 불가능하다.

- 커밋 전 **Unity에서 저장하고 에디터를 닫은 상태**인지 확인한다. (열어둔 채 커밋하면 파일이 어긋날 수 있음)
- 씬/프리팹이 여러 사람에 의해 수정되고 있지 않은지 확인한다(한 씬은 한 사람 원칙).

## 4. 대용량 파일 / LFS

- Git LFS로 관리되는 확장자(`.fbx`, 텍스처 등)는 `.gitattributes` 설정을 확인한다.
- 100MB 넘는 파일은 LFS 없이 커밋하면 GitHub이 거부한다.

## 5. 커밋 크기

- "한 단위가 끝날 때마다" 작게 커밋한다. 하루치 전부를 한 커밋으로 묶지 않는다.

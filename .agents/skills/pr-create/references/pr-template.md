# PR 본문 템플릿

## 제목 표준
```
<type>: <요약> (#<N>)
```
예시: `feat: 근접 상호작용 대상 우선순위 판정 (#6)`

## 본문 구조

```markdown
## 관련 이슈
Closes #<N>

## 요약
<이 PR이 무엇을 하는지 1~3줄>

## 이슈 대비 변경 사항
- (이슈) <계획> → (실제) <구현>
  · 이유: <커밋 근거 또는 사용자 확인>
- (미구현) <항목> → <후속 이슈/보류 사유>

## 변경 상세
- <변경 요약>
- <변경 요약>

## 접근 이유
<설계 선택의 근거. 이슈 계획과 다른 지점이 있으면 여기서도 설명>

## 검증
- <어떻게 확인했는지>

## 테스트 방법
1. <재현/테스트 절차>

## 참고/주의
- <알려진 제약, 후속 작업>

## 통계
<files changed, +추가 / −삭제>
```

### 섹션별 규칙
- **`## 이슈 대비 변경 사항`**: 이슈는 계획, PR은 실제 결과다. 이슈 요구사항과 실제 구현을 항목별로 대조한 결과를 적는다. 차이가 없으면 "이슈 계획대로 구현" 한 줄로 끝낸다. **커밋에서 이유를 알 수 없으면 추측하지 말고 사용자에게 질문**해 채운다.
- **`Closes #<N>`**: 병합 시 이슈가 자동 종료되도록 연결한다.
- 나머지 섹션은 저장소 관례와 변경 성격에 맞게 조정한다.
- 본문은 `--body-file`로 전달해 한국어·줄바꿈·`` # ``·백틱 이스케이프 문제를 피한다.

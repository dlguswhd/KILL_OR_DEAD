# git 워크플로우 (git-workflow)

git 협업 작업의 **전체 루틴을 안내하고, 현재 상태를 진단해 다음 단계로 라우팅**한다. 이 스킬은 직접 실행하지 않는다 — 각 단계의 실행은 해당 스킬이 담당한다.

## 루틴 개요

| 단계 | 내용 | 담당 스킬 |
|---|---|---|
| 1 | 진행할 작업을 설명하는 이슈 생성 | `issue-create` |
| 2 | 이슈 성격·번호로 브랜치 생성 (`<type>/#<N>`) | `branch-create` |
| 3 | 작업하며 커밋 (간단 커밋 → 양식 수정 → push) | `commit` |
| 4 | 기능 개발이 충분히 진행되면 PR 생성 | `pr-create` |

## 현재 상태 진단

다음을 실행해 **지금 어느 단계인지** 판별한다.
```
git status -sb
git branch --show-current
git log --oneline -5
```
- 현재 브랜치명이 `<type>/#<N>` 패턴인지 확인 (예: `feat/#6`)
- 작업 트리 변경 여부 확인

## 단계별 라우팅

분기 규칙:
- **이슈가 없음** → 1단계: `issue-create` 스킬의 절차를 따른다
- **이슈는 있고 작업 브랜치가 없음** → 2단계: `branch-create` 스킬의 절차를 따른다
- **작업 브랜치에서 변경/커밋이 진행 중** → 3단계: `commit` 스킬의 절차를 따른다
- **이슈의 기능 개발이 충분히 진행됨** → 4단계: `pr-create` 스킬의 절차를 따른다

각 단계 핵심 요약(형제 스킬이 함께 설치돼 있으면 그 절차를 그대로 따른다):

- **1. 이슈**: `gh` 확인(없으면 설치 안내) → type 추론 → 표준 제목(`<type>: <명사구>`)/라벨 → `gh issue create` → 이슈 번호 보고
- **2. 브랜치**: 이슈 번호로 이슈 조회 → type 파싱 → `git switch -c "<type>/#<N>"`
- **3. 커밋**: 사전 점검(금지 파일·Unity) → 저장소 관례 탐지 → 커밋 또는 마지막 커밋 `--amend`(push 전) → 확인 후 실행, **push는 사용자가**
- **4. PR**: 브랜치에서 이슈 번호 파싱 → 커밋/변경 분석 → **이슈(계획)와 실제 구현 대조, 차이·이유 정리(불명확하면 사용자에게 질문)** → `gh pr create`

## 협업 수칙

- **작업 시작 전 `git fetch` → `pull`** (충돌 예방). Pull 없이 시작하면 충돌이 확정된다.
- 저장소는 **비공개 유지** (유료 에셋 라이선스 보호).
- **커밋은 작게, 자주** — "오늘 한 거 전부"보다 기능 단위로.
- `main`은 항상 돌아가는 상태로 유지하고, 작업은 브랜치에서 한다.
- **(Unity / 대용량 바이너리 프로젝트라면)** 한 씬은 한 사람만 건드리기, 에디터 버전 통일, `.meta` 동반 커밋, 대용량은 LFS. 상세 점검은 `commit` 스킬(`references/unity-git-guard.md`)이 담당한다.

## 규칙 우선순위

1. **사용자가 이번 대화에서 제시한 규칙/문서 내용**
2. 이 스킬에 내장된 일반 루틴 (위 내용)

특정 파일에 종속되지 않는다. 별도 규칙 파일을 참조하거나 탐지하지 않고, 내장 루틴으로 동작한다. 저장소의 실제 관례(접두사·라벨 등)는 각 단계 스킬이 실행 시 `git log`·`gh label list`로 확인한다.

## 사용자 예시 문구

- 1단계: `어떤 기능을 지금부터 개발할 건데 계획용 이슈 좀 만들어줘.`
- 2단계: `5번 이슈로 브랜치 파줘.` (리팩토링이면 `refactor/#5`, 기능 개발이면 `feat/#5`)
- 3단계: `간단하게 내 의도를 설명해서 커밋을 작성했어. 마지막 커밋을 양식에 맞게 수정해줘.`
- 4단계: `이 브랜치의 이름에 있는 이슈 번호를 확인하고, 이 브랜치에서 진행된 커밋을 확인해. 기능 개발이 완료되었다고 판단한다면 PR을 생성해줘.`

## 주의사항

- 이 스킬은 **안내·진단·라우팅만** 한다. 실제 이슈/브랜치/커밋/PR 생성은 각 단계 스킬이 수행한다.
- 특정 파일이나 외부 도구에 종속되지 않는다.
- 상태 진단 결과와 다음 단계를 간결히 제시한 뒤, 사용자의 확인을 받아 진행한다.

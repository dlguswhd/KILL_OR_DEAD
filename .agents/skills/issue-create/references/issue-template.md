# 이슈 본문 템플릿 · 표준

## 제목 표준

```
<type>: <한글 명사구 요약>
```

예시: `feat: 근접 상호작용 대상 우선순위 판정`

- type은 커밋과 동일한 어휘를 쓴다: `feat`, `fix`, `refactor`, `docs`, `chore`, `test`, `perf`, `style`
- 이슈는 "무엇을 할지"의 제목이므로 커밋의 `~함` 종결 대신 **명사구**로 쓴다.

### type → 라벨 매핑

| type | 라벨 |
|---|---|
| `feat` | `enhancement` |
| `fix` | `bug` |
| `refactor` | `enhancement` |
| `docs` | `documentation` |
| `chore` / `test` / `perf` / `style` | (없음) |

- `blocked`는 타입이 아니라 **추가 라벨**로만 사용한다(선행 이슈에 막힌 경우).
- 라벨이 저장소에 없으면 생략한다. **라벨을 임의로 새로 만들지 않는다.**

## 본문 구조

```markdown
## 배경
<왜 이 작업이 필요한가>

## 요구사항
1. <요구사항>
2. <요구사항>

## 메커니즘 (선택)
<플로차트/시퀀스 등이 필요하면 mermaid 블록>

## 완료 조건
- [ ] <검증 가능한 조건>
- [ ] <검증 가능한 조건>

## 참고
- <관련 문서/노트/이슈 링크>
```

- 완료 조건은 반드시 체크리스트(`- [ ]`)로 작성한다 (PR 단계에서 `pr-create`가 이 조건과 실제 구현을 대조한다).
- 저장소에 `.github/ISSUE_TEMPLATE`가 있으면 그 구조를 우선한다.
